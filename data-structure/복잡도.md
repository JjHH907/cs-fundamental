# 복잡도
<br />

## 1. 복잡도란?

cs에서의 복잡도는 알고리즘이 머리로 이해하기 얼마나 어렵냐가 아니다.
입력이 커질 때 그 알고리즘이 시간과 메모리를 얼마나 쓰는지 재는 척도이다.

복잡도는 주로 두 가지로 나눈다.

- 시간 복잡도: 입력 크기 n이 커질수록 연산이 몇 번 일어나는지
- 공간 복잡도: 입력 크기 n이 커질수록 추가로 필요한 메모리가 얼마나 늘어나는지

같은 문제를 푸는 방법이 여러 개면, 큰 입력에서 어느 쪽이 버틸 수 있는지 이걸로 비교한다.

예를 들어 원소 n개를 정렬할 때 선택 정렬은 비교가 대략 n²번, 병합 정렬은 대략 n log n번이다.
n = 10이면 둘 다 금방 끝난다. n = 10⁷이면 선택 정렬은 사실상 안 끝나고 병합 정렬은 수 초 안에 끝난다.
그래서 알고리즘을 설계할 때는 복잡도를 줄이는 쪽으로 가는 게 기본이다.

다만 복잡도가 낮다고 항상 최선은 아니다. 구현이 얼마나 쉬운지, 상수배가 큰지, 메모리가 넉넉한지, 입력이 원래 작은지도 같이 본다.

여기서 n은 보통 이런 뜻으로 쓴다.

- 배열, 리스트, 정렬, 탐색: 원소 개수
- 문자열: 문자 개수
- 그래프: 정점 수 V, 간선 수 E
- 행렬: 행·열 크기
- 큰 수 연산: 비트 수나 자릿수

실제 몇 초 걸리는지는 CPU, 언어, 컴파일러, 캐시에 따라 바뀐다.
그래서 분석할 때는 “이 기계에서 몇 초”가 아니라, n이 커질 때 연산 횟수가 어떤 식으로 늘어나는지를 본다.
<br />

## 2. 시간 복잡도

알고리즘이 실행되는 데 걸리는 시간을 입력 크기 n과 관련지어 나타낸 것이다.
몇 초가 아니라, 기본 연산이 몇 번 도는지 n에 대한 식으로 적는다.

예를 들어:

```c
int sum = 0;                 // 1번
for (int i = 0; i < n; i++) { // 조건 검사 약 n+1번, i++ n번
    sum += i;                // n번
}
```

n이 커지는 만큼 반복 횟수도 같이 커진다.
이 코드는 n에 비례해서 시간이 늘어나므로 시간 복잡도는 Θ(n)이다. 보통은 O(n)이라고 말한다.

### 왜 초 단위로 안 재나

같은 O(n) 코드라도 C로 짠 것과 파이썬으로 짠 것, 노트북과 서버, 캐시에 다 들어가는 배열과 디스크를 오가는 데이터는 실제 초가 다르다.
반대로 “n이 10배가 되면 일도 대략 10배가 된다”는 증가 비율은 환경이 바뀌어도 비슷하게 유지된다.
시험이나 면접에서 복잡도를 묻는 이유가 이것이다.

기본 연산으로 보통 세는 것:

- +, -, *, /, %
- 비교
- 대입
- 배열이나 포인터 접근
- 함수 호출 한 번 (함수 몸체는 따로 계산)

한 줄이 내부에서 무거운 경우도 있다. sort(), 해시 테이블 리해시, 파일 입출력 같은 건 그 함수의 복잡도를 가져와서 더한다.
<br />

### 점근적 표기법

n이 충분히 클 때의 증가 추세만 남긴다. 상수와 낮은 차수 항은 버린다.
수행 시간을 T(n)이라고 하자.

#### O (Big-O)

상한이다. “많아 봐야 이 정도”라는 뜻이다.

T(n) = O(f(n)) 이면 상수 c > 0, n₀ > 0가 있어서
n ≥ n₀일 때 T(n) ≤ c · f(n) 이다.

예: T(n) = 3n² + 100n + 50 이면 T(n) = O(n²)이다.
c = 4로 두고 n을 크게 잡으면 3n² + 100n + 50 ≤ 4n² 이 된다.

정의만 보면 3n² + 100n = O(n³)도 맞다. O는 상한이라 더 큰 함수로 씌워도 성립하기 때문이다.
다만 적을 때는 가장 잘 맞는 쪽을 고른다. 저 식은 O(n²)라고 쓰는 게 맞다.

#### Ω (Big-Omega)

하한이다. “적어도 이 정도는 한다”는 뜻이다.

n ≥ n₀일 때 T(n) ≥ c · f(n)

배열에서 최댓값을 찾으려면 원소를 전부 봐야 하므로, 어떤 알고리즘을 쓰든 Ω(n)이다.

#### Θ (Big-Theta)

상한과 하한이 같을 때다. T(n)이 f(n)과 같은 차수로 증가한다는 뜻이다.

c₁ f(n) ≤ T(n) ≤ c₂ f(n)

위의 합 구하기 반복문은 Θ(n)이다.
수업이나 코테 풀이에서는 Θ 대신 O로 적는 경우가 많다. 의미가 조금 다르다는 것만 알아두면 된다.

#### 적을 때 습관

1. 제일 빨리 커지는 항만 남긴다.
   5n³ + 2n² + 1000 → O(n³)
2. 계수 버린다.
   100n → O(n)
3. 로그의 밑은 보통 안 적는다.
   log₂ n이든 log₁₀ n이든 상수배 차이라 O(log n)으로 같다.
4. 입력이 여러 개면 변수를 다 적는다.
   그래프는 O(V + E), 길이가 다른 두 배열은 O(n + m)

O(2n)과 O(n)은 같다. 상수까지 말하고 싶으면 “비교가 약 2n번”처럼 횟수를 직접 센다.
<br />

### 최선, 평균, 최악

같은 알고리즘이라도 입력이 어떻게 생겼느냐에 따라 T(n)이 달라진다.

배열에서 값 x를 찾는 선형 탐색:

```c
int linear_search(int a[], int n, int x) {
    for (int i = 0; i < n; i++) {
        if (a[i] == x) return i;
    }
    return -1;
}
```

- 최선: x가 맨 앞에 있다. 비교 1번. O(1)
- 최악: 없거나 맨 뒤에 있다. 비교 n번. O(n)
- 평균: x가 모든 칸에 같은 확률로 있고 반드시 있다면 약 n/2번. 그래도 O(n)

비교할 때는 최악을 기본으로 쓴다.
실시간 서비스에서는 가끔 들어오는 최악의 입력이 장애가 되고, 평균은 입력 분포를 가정해야 해서 그 가정이 틀리면 의미가 없어지기 때문이다.

평균이 중요한 경우도 있다.

- 해시 테이블 탐색: 평균 O(1), 최악 O(n)
- 퀵 정렬: 평균 O(n log n), 최악 O(n²) (피벗이 매번 최소나 최대)

퀵 정렬처럼 최악이 나쁘면 피벗을 랜덤으로 고르거나, 인트로소트처럼 최악의 길을 감지하고 힙 정렬로 넘어간다.
<br />

### 코드에서 세는 방법

가장 많이 실행되는 줄이 몇 번 도는지 센 다음, 점근적으로 정리하면 된다.

#### 단순 반복

```c
for (int i = 0; i < n; i++) {
    // O(1) 작업
}
```

몸체가 O(1)이면 전체 O(n).

#### 중첩 반복, 안쪽 범위가 n으로 고정

```c
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        // O(1)
    }
}
```

바깥 n번 × 안쪽 n번 = n² → O(n²)
3중이면 O(n³). 평범한 행렬 곱이 이 형태다.

#### 안쪽 범위가 i에 의존하는 경우

```c
for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {
        // O(1)
    }
}
```

안쪽 횟수: n + (n-1) + … + 1 = n(n+1)/2 = Θ(n²)

삼각형이라 n²/2이지, 점근적으로는 그냥 이중 루프와 같은 O(n²)다.
중첩이 두 겹이면 무조건 n²인 건 아니고, 실제 반복 횟수의 합을 구해야 한다. 그 합이 n²인 경우가 많을 뿐이다.

다른 예:

```c
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= i * i; j++) {
        // O(1)
    }
}
```

안쪽이 i²번이므로 합은 Σ i² = n(n+1)(2n+1)/6 = Θ(n³)

중첩 루프라고 해서 항상 n²가 되는 것도 아니다.

```c
for (int i = 0; i < n; i++) {
    for (int j = 1; j <= n; j *= 2) {
        // O(1)
    }
}
```

안쪽은 j가 1, 2, 4, …, n이라 log n번이다. 전체는 O(n log n).
안쪽이 `j < 3`처럼 상수 번이면 전체는 O(n)이다.

#### 반복 변수가 절반씩 줄 때

```c
for (int i = n; i > 0; i /= 2) {
    // O(1)
}
```

n, n/2, n/4, …, 1 이므로 약 log₂ n번 → O(log n)

이진 탐색이 이쪽이다.

```c
int binary_search(int a[], int n, int x) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == x) return mid;
        else if (a[mid] < x) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

매 단계마다 구간이 절반이 되므로 최악 O(log n).
전제는 배열이 이미 정렬돼 있어야 한다는 것이다. 정렬하는 비용 O(n log n)은 따로 생각해야 한다.

#### 코드가 이어지면 더한다

```c
for (int i = 0; i < n; i++) { ... }   // O(n)
sort(a, a + n);                      // O(n log n)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) { ... } // O(n²)
```

전체는 O(n) + O(n log n) + O(n²) = O(n²)
여러 항을 더하면 제일 큰 항이 남는다.

#### 조건문

```c
if (sorted) {
    binary_search(...);  // O(log n)
} else {
    linear_search(...);  // O(n)
}
```

최악을 보면 O(n)이다.
두 분기가 다르면 비싼 쪽을 최악으로 잡는다.
입력이 항상 sorted == true라는 보장이 있을 때만 O(log n)이라고 말할 수 있다.

#### 함수 호출

```c
for (int i = 0; i < n; i++) {
    f(a, n);  // f가 O(n)이면
}
```

바깥 n번 × f의 O(n) = O(n²)

자주 쓰는 연산의 복잡도:

- 배열 인덱스 접근 a[i]: O(1)
- 동적 배열 맨 끝 push: 평균 O(1) (상각)
- 동적 배열 중간 insert: O(n)
- 연결 리스트 맨 앞 insert: O(1)
- 연결 리스트 k번째 접근: O(k)
- 균형 BST 탐색/삽입/삭제: O(log n)
- 해시맵 탐색/삽입: 평균 O(1)
- 일반적인 sort: O(n log n)

코드가 한 줄이라고 O(1)은 아니다. 그 한 줄이 sort(a, a+n)이면 O(n log n)이다.
<br />

#### 재귀

재귀는 점화식을 세운 뒤 푼다.

팩토리얼:

```c
long long fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

T(n) = T(n-1) + Θ(1), T(1) = Θ(1)
→ T(n) = Θ(n)

피보나치 나이브:

```c
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

T(n) = T(n-1) + T(n-2) + Θ(1)
호출 트리가 거의 이진트리처럼 커지고, 같은 부분 문제를 반복해서 계산한다.
T(n) = Θ(φⁿ) (φ ≈ 1.618). 보통 O(2ⁿ)으로 적는다.

메모이제이션이나 DP를 쓰면 부분 문제 n개를 각 한 번만 푸므로 O(n)이 된다.
점화식이 같아도 구현에 따라 복잡도는 완전히 달라진다.

병합 정렬:

- 배열을 반으로 나눈다. O(1)
- 왼쪽 T(n/2), 오른쪽 T(n/2)
- 두 배열을 합친다. O(n)

T(n) = 2T(n/2) + Θ(n), T(1) = Θ(1)

이 형태는 마스터 정리로 풀 수 있다.
T(n) = a T(n/b) + O(nᵏ) (a ≥ 1, b > 1) 이고 p = log_b a 라고 하면

- k < p 이면 T(n) = Θ(nᵖ)
- k = p 이면 T(n) = Θ(nᵖ log n)
- k > p 이면 T(n) = Θ(nᵏ)

병합 정렬은 a=2, b=2, k=1 이라 p=1=k 이므로 Θ(n log n)
이진 탐색을 재귀로 쓰면 a=1, b=2, k=0 이라 Θ(log n)

모든 재귀가 이 형태인 건 아니다. 안 맞으면 재귀 트리를 그려서 층마다 일을 더한다.
<br />

### 자주 나오는 시간 복잡도

느리게 증가하는 것부터 적으면

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

n이 커질수록 오른쪽으로 갈수록 감당이 안 된다.
작은 n에서는 상수가 큰 O(n log n)이 O(n²)보다 느릴 수도 있다.

#### O(1)

n과 상관 없이 끝난다.

```c
int get_first(int a[], int n) {
    return a[0];
}

int add(int x, int y) {
    return x + y;
}
```

해시 테이블 평균 탐색, 배열 임의 접근, 스택 push/pop이 여기 들어간다.

#### O(log n)

한 번에 문제 크기를 몇 분의 1로 줄일 때 나온다.
n = 1,000,000이어도 log₂ n ≈ 20이라 매우 빠르다.

정렬된 배열 이진 탐색, 균형 BST, 힙 삽입/삭제, n을 2로 나누는 루프가 이쪽이다.

거듭제곱을 그냥 구하면 O(n)이고, 아래처럼 나누면 O(log n)이다.

```c
long long pow_fast(long long x, long long n) {
    long long res = 1;
    while (n > 0) {
        if (n & 1) res *= x;
        x *= x;
        n >>= 1;
    }
    return res;
}
```

#### O(n)

입력을 한두 번 훑는다.

```c
int find_max(int a[], int n) {
    int m = a[0];
    for (int i = 1; i < n; i++)
        if (a[i] > m) m = a[i];
    return m;
}
```

최댓값은 모든 원소를 안 보면 확정할 수 없어서, 비교만 쓰는 모델에서는 Ω(n)이기도 하다.
이 문제는 Θ(n)이 최선이다.

배열 합, 카운팅, 정렬된 두 배열 병합, 연결 리스트 한 번 순회가 같다.
입력 전체를 읽어야 하는 문제에서 O(n)보다 빠를 수는 없다.

#### O(n log n)

비교 정렬의 일반적인 하한이 이 근처다.
가능한 순열이 n!개인데, 비교로 그걸 나누려면 결정 트리 높이가 log₂(n!) ≈ n log n이 된다.

병합 정렬, 힙 정렬, 평균적인 퀵 정렬, 인트로소트,
세그먼트 트리/펜윅으로 n번 갱신하거나 질의하는 경우가 여기 해당한다.

n = 10⁶이면 n log₂ n ≈ 2×10⁷ 이라 1초 제한에 보통 들어온다.
같은 n의 n² = 10¹²는 시간 초과다.

#### O(n²), O(n³)

이중/삼중 루프, 모든 쌍이나 세 쌍을 보는 코드.

```c
int max_pair_sum(int a[], int n) {
    int ans = INT_MIN;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] + a[j] > ans) ans = a[i] + a[j];
    return ans;
}
```

이건 O(n²)이지만, 사실 최댓값과 두 번째 최댓값만 보면 O(n)이다.
같은 문제를 O(n²)로 푸는 것과 O(n)으로 푸는 차이가 복잡도 공부의 포인트다.

버블/선택/삽입 정렬은 O(n²)
평범한 행렬 곱과 플로이드-워셜은 O(n³), O(V³)
구간 dp[i][j]를 채울 때 가운데를 O(n)으로 돌리면 전체가 O(n³)

n = 10⁴의 n²는 10⁸ 근처라 언어와 상수에 따라 아슬아슬하다.
n = 400의 n³도 비슷한 규모다.

#### O(2ⁿ), O(n!)

입력이 조금만 커져도 감당이 안 된다.

부분집합 전수 조사는 O(2ⁿ × (부분집합 하나 처리 비용))이다.

```c
void subsets(int idx, int n) {
    if (idx == n) { /* 한 부분집합 처리 */ return; }
    subsets(idx + 1, n);  // idx 안 넣음
    subsets(idx + 1, n);  // idx 넣음
}
```

n = 20이면 약 100만, n = 40이면 1조.

순열 전수 조사는 O(n!)

```c
void permute(int depth, int n) {
    if (depth == n) { /* 순열 하나 처리 */ return; }
    for (int i = 0; i < n; i++) {
        if (used[i]) continue;
        used[i] = 1;
        permute(depth + 1, n);
        used[i] = 0;
    }
}
```

n = 10이면 10! = 3,628,800
n = 13이면 이미 62억.

외판원 문제를 그냥 돌리면 이 부류다. DP로 O(n² 2ⁿ)까지는 줄일 수 있어도 다항 시간은 아니다.
지수 시간이 틀린 건 아니다. n ≤ 20인 문제에서는 일부러 2ⁿ을 쓴다.
중요한 건 n의 상한을 보고 가능한 쪽을 고르는 것이다.
<br />

### 같은 문제를 여러 방법으로

문제: 정렬된 배열에서 두 수의 합이 S인 쌍이 있는가.

모든 쌍을 보면 O(n²)

```c
bool two_sum_naive(int a[], int n, int S) {
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (a[i] + a[j] == S) return true;
    return false;
}
```

각 a[i]에 대해 S - a[i]를 이진 탐색하면 O(n log n)

```c
bool two_sum_bs(int a[], int n, int S) {
    for (int i = 0; i < n; i++) {
        if (binary_search(a + i + 1, a + n, S - a[i])) return true;
    }
    return false;
}
```

이미 정렬돼 있으니 투 포인터로 O(n)

```c
bool two_sum_two_pointers(int a[], int n, int S) {
    int i = 0, j = n - 1;
    while (i < j) {
        int s = a[i] + a[j];
        if (s == S) return true;
        if (s < S) i++;
        else j--;
    }
    return false;
}
```

세 방법 다 맞다.
n = 10⁵이면 첫 번째는 불가능하고, 두 번째는 되고, 세 번째가 제일 가볍다.
배열이 정렬되어 있지 않다면 투 포인터를 쓰기 전에 정렬 O(n log n)이 필요하고, 그때 전체는 O(n log n)이 된다.
전제 조건을 복잡도에 포함해야 한다.

피보나치 n번째 수도 마찬가지다.

- 나이브 재귀: 시간 O(2ⁿ), 공간 O(n) (콜스택)
- 메모이제이션: 시간 O(n), 공간 O(n)
- 반복 DP: 시간 O(n), 공간 O(n) 또는 최근 두 개만 남기면 O(1)
- 행렬 거듭제곱: 시간 O(log n), 공간 O(1)

“피보나치는 O(2ⁿ)이다”가 아니다. 그 구현이 O(2ⁿ)인 것이다.
<br />

### n이 커질 때 감

1초에 대략 10⁸ ~ 5×10⁸번 연산한다고 보면 된다. 언어와 상수에 따라 다르다.

- n = 10
  log n ≈ 3, n = 10, n log n ≈ 33, n² = 100, n³ = 1000, 2ⁿ = 1024, n! ≈ 3.6×10⁶
- n = 20
  n² = 400, n³ = 8000, 2ⁿ ≈ 10⁶, n! 은 이미 10¹⁸ 근처
- n = 60
  2ⁿ ≈ 10¹⁸
- n = 10³
  n log n ≈ 10⁴, n² = 10⁶, n³ = 10⁹
- n = 10⁵
  n log n ≈ 1.7×10⁶, n² = 10¹⁰
- n = 10⁶
  n log n ≈ 2.0×10⁷, n² = 10¹²
- n = 10⁸
  n 자체만 해도 10⁸, n log n ≈ 2.7×10⁹

코테에서 입력 제한을 보고 역으로 가늠할 때:

- n ≤ 10 → n! 가능
- n ≤ 20 → 2ⁿ · n, 2ⁿ · n² 검토
- n ≤ 400 → n³
- n ≤ 5000 → n²
- n ≤ 10⁵ → n log n 또는 n
- n ≤ 10⁷ → n, 상수가 작은 n log n
- n ≤ 10¹⁸ → log n 또는 O(1). 수식, 이분 탐색, 행렬 거듭제곱

절대 법칙은 아니다. 상수가 큰 O(n log n)은 n = 10⁵에서도 느릴 수 있다.
<br />

### 상각 분석

연산 하나가 가끔 O(n)이어도, 연속 n번의 평균이 O(1)일 수 있다.

동적 배열(vector, ArrayList)의 push_back이 그렇다.
용량이 남아 있으면 O(1)이고, 가득 차면 두 배 크기로 재할당하면서 전부 복사해서 그 한 번은 O(n)이다.

용량이 1, 2, 4, …, n으로 늘어난다고 하면 복사 총합은
1 + 2 + 4 + … + n ≤ 2n
n번 push의 총비용이 O(n)이므로 한 번의 상각 비용은 O(1)이다.
최악 한 방은 O(n)이지만, 그 전에 싼 연산이 많이 쌓여 평균을 깎는다.

말할 때는 “최악 O(n), 상각 O(1)”처럼 구분해 적으면 정확하다.
<br />

## 3. 공간 복잡도

알고리즘이 실행되는 동안 사용하는 메모리량을 입력 크기 n의 함수로 나타낸 것이다.
시간도 점근적으로 보듯, 공간도 보통 O로 나타낸다.

공간을 두 층으로 나누면 덜 헷갈린다.

1. 입력 공간: 문제에서 이미 주어진 배열, 그래프, 문자열. 크기 Θ(n)인 경우가 많다.
2. 보조 공간: 알고리즘이 추가로 만든 배열, 재귀 스택, 해시맵 같은 것.

“공간 복잡도 O(1)”이라고 하면 대부분 보조 공간이 상수라는 뜻이다.
입력 배열까지 세면 거의 모든 알고리즘이 O(n)이 되어서 비교가 안 된다.

총 사용 공간 = 입력 + 보조 + 구현 오버헤드
분석할 때는 보조 공간을 기본으로 센다.
문제가 “추가 배열 없이 in-place로 하라”면 보조 O(1)을 요구하는 것이다.
<br />

### 기본 예

보조 O(1)

```c
int sum = 0;
for (int i = 0; i < n; i++) sum += a[i];
```

변수 sum, i만 쓴다. 배열 a는 입력이다.

선택 정렬도 교환용 임시 변수 몇 개만 쓰므로 보조 O(1)이다. 시간은 O(n²)이다.

보조 O(n)

```c
int* b = malloc(sizeof(int) * n);
for (int i = 0; i < n; i++) b[i] = a[i] * 2;
```

크기 n짜리 배열을 새로 만들었다.

병합 정렬은 합칠 때 같은 크기 임시 배열이 필요해서 보통 보조 O(n)이다.
힙 정렬은 제자리로 구현하면 보조 O(1)에 가깝다.

카운팅 정렬, 기수 정렬은 값의 범위 k에 비례하는 버킷이 필요하다. 보조 O(n + k)
k가 n보다 훨씬 크면 공간이 먼저 터진다.
<br />

### 재귀와 호출 스택

재귀는 배열을 안 만들어도 호출 깊이만큼 스택 프레임을 쓴다.

```c
int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
```

깊이가 n이므로 보조 공간 O(n)
컴파일러가 꼬리 재귀를 최적화하면 O(1)이 될 수는 있다. 언어와 옵션에 따라 달라서, 분석할 때는 보통 스택을 센다.

이진 탐색을 재귀로 쓰면 깊이가 log n이라 보조 O(log n)
같은 알고리즘을 반복문으로 바꾸면 보조 O(1)

나이브 피보나치 재귀는 동시에 쌓이는 깊이가 n이라 보조 O(n)이다.
시간은 O(2ⁿ)인데 공간은 O(n)이다. 시간과 공간은 따로 적어야 한다.

트리 DFS를 재귀로 하면 최악 깊이가 h다. 한쪽으로 치우친 트리면 h = n이라 스택 O(n)
BFS는 큐에 한 레벨이 들어갈 수 있어서 최악 O(n)
<br />

### 자료구조가 공간을 결정하는 경우

알고리즘 본문보다 무엇을 저장하느냐가 공간을 결정하는 경우가 많다.

- 배열, 동적 배열: O(n)
- 연결 리스트: O(n). 포인터 때문에 원소 하나당 메모리가 배열보다 크다
- 해시 테이블: 평균 O(n). 로드 팩터만큼 빈 칸이 있다
- 균형 BST: O(n)
- n × n 인접 행렬: O(n²)
- 인접 리스트: O(V + E)
- 세그먼트 트리: 대략 4n칸이니 O(n)
- DP 테이블 dp[n][m]: O(nm)

정점 10만, 간선 10만인 그래프에서 인접 행렬은 10¹⁰칸이라 불가능하고 인접 리스트 O(V+E)만 된다.
시간뿐 아니라 공간 한도가 자료구조 선택을 강제한다.
<br />

### DP에서 공간을 줄이는 방법

시간 O(n²)인 DP가 공간도 O(n²)일 필요는 없다.

0-1 배낭에서 dp[i][w]가 바로 이전 행 dp[i-1][*]만 보면 한 줄만 남길 수 있다.

```c
// 시간 O(N W), 공간 O(W)
for (int i = 1; i <= N; i++)
    for (int w = W; w >= wt[i]; w--)
        dp[w] = max(dp[w], dp[w - wt[i]] + val[i]);
```

피보나치도 dp[0..n] 대신 직전 두 값만 두면 보조 O(1)이다.
점화식이 참고하는 범위만 남기면 된다.
<br />

### 시간과 공간을 맞바꾸는 경우

한쪽을 줄이면 다른 쪽이 늘어나는 경우가 많다.

계산 결과를 저장하면 시간은 줄고 공간은 는다.
피보나치 나이브는 시간 O(2ⁿ)에 공간 O(n)이고, 메모이제이션을 하면 시간 O(n)에 공간 O(n)이 된다.

sin 값을 매번 계산하지 않고 배열에 넣어 두면 조회는 O(1), 공간은 O(k)다.

중복을 찾을 때 해시셋을 쓰면 시간 O(n), 공간 O(n)
정렬한 뒤 인접한 것만 비교하면 시간 O(n log n), 보조 공간은 O(1) 또는 O(log n)

힙 정렬은 병합 정렬보다 공간이 작다. 대신 실측 시간이나 안정성에서 손해를 보기도 한다.

n개의 존재 여부만 필요하면 bool 배열 대신 비트셋으로 공간을 32~64배 줄일 수 있다. 시간은 비슷한 O(n)이다.

공간이 부족한 환경에서는 O(n²) 테이블이 시간보다 먼저 터진다.
64MB는 int 기준 대략 1.6×10⁷칸이다. n = 5000인 int dp[n][n]은 이미 100MB 근처다.
<br />

### 시간이랑 공간을 같이 적어 보면

- 배열 최댓값: 시간 O(n), 보조 O(1)
- 이진 탐색(반복): 시간 O(log n), 보조 O(1)
- 이진 탐색(재귀): 시간 O(log n), 보조 O(log n)
- 선형 탐색: 시간 O(n), 보조 O(1)
- 선택/삽입/버블 정렬: 시간 O(n²), 보조 O(1)
- 병합 정렬: 시간 O(n log n), 보조 O(n)
- 힙 정렬: 시간 O(n log n), 보조 O(1)
- 퀵 정렬: 평균 시간 O(n log n) / 최악 O(n²), 스택은 평균 O(log n) / 최악 O(n)
- 카운팅 정렬: 시간 O(n + k), 보조 O(k)
- 나이브 피보나치: 시간 O(2ⁿ), 보조 O(n)
- DP 피보나치: 시간 O(n), 보조 O(n) 또는 O(1)
- 플로이드-워셜: 시간 O(V³), 공간 O(V²)
- DFS (인접 리스트): 시간 O(V+E), 공간 O(V) (방문 배열 + 스택)
- BFS: 시간 O(V+E), 공간 O(V)

한 줄로 말할 때는 “병합 정렬은 시간 O(n log n), 공간 O(n)”처럼 둘 다 적는다.
<br />

처음 코드로 돌아가면

```c
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += i;
}
```

루프가 n번이므로 시간은 Θ(n)
추가 배열이 없고 변수만 몇 개라 보조 공간은 Θ(1)
