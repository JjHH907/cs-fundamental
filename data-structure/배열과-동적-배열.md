# 배열과 동적 배열
<br />

## 1. 배열이란

배열은 같은 타입의 값을 메모리에 한 줄로 붙여 놓은 자료구조다.
이름은 여러 개가 아니라 하나고, 각 칸은 0부터 시작하는 인덱스로 구분한다.

```c
int a[5] = {10, 20, 30, 40, 50};
// a[0] == 10, a[4] == 50
```

붙어 있다는 게 전부다. 첫 칸의 주소만 알면 i번째 칸의 주소는

    시작 주소 + i * (원소 하나 크기)

로 바로 계산된다. 그래서 접근이 O(1)이다.
연결 리스트처럼 다음 칸을 따라갈 필요가 없다.

C에서 크기가 컴파일 타임에 정해진 배열을 정적 배열이라고 부른다.
함수 안에 선언하면 보통 스택에 올라가고, 전역이면 데이터 영역에 올라간다.
한 번 정한 크기는 실행 중에 바꿀 수 없다.

```c
int a[100];        // 칸 100개. 나중에 101개가 필요하면 이 배열로는 안 된다
int b[n];          // C99 VLA. 동작은 하지만 코테/실무에서는 잘 안 쓴다
```

크기를 실행 중에 정하고 싶으면 malloc으로 힙에 직접 잡거나, 아래에서 볼 동적 배열을 쓴다.

```c
int *a = malloc(sizeof(int) * n);
// ...
free(a);
```

이건 “크기를 변수로 정한 배열”이지, 아직 동적 배열은 아니다.
칸이 모자라면 직접 더 큰 덩어리를 다시 할당하고 복사해야 한다.
동적 배열은 그 과정을 자료구조가 대신 해 주는 것이다.
<br />

## 2. 배열로 할 수 있는 일

### 인덱스로 읽고 쓰기

```c
a[i] = 7;
int x = a[i];
```

시간 O(1), 추가 공간 O(1)
n이 100이든 1억이든 한 칸 접근 비용은 같다.
다만 1억 칸이면 그 배열을 만들기만 해도 공간이 O(n)이다.

### 전체 순회

```c
int sum = 0;
for (int i = 0; i < n; i++) sum += a[i];
```

시간 O(n)
칸이 붙어 있어서 CPU 캐시와 궁합이 좋다. 한 칸을 읽으면 옆 칸도 같이 캐시에 올라오는 경우가 많다.
같은 n개를 연결 리스트로 순회하면 노드가 여기저기 흩어져 있어서 같은 O(n)이라도 실제 시간이 더 나오는 경우가 많다.

### 선형 탐색

```c
int find(int a[], int n, int x) {
    for (int i = 0; i < n; i++)
        if (a[i] == x) return i;
    return -1;
}
```

최악 O(n)
정렬이 안 되어 있으면 이보다 빠르게 찾는 일반적 방법은 없다.
정렬이 되어 있으면 이진 탐색으로 O(log n)이다. 그 전제는 복잡도 노트에서 본 그대로다.

### 중간 삽입, 중간 삭제

i번 칸에 값을 끼워 넣으려면 i 이후를 한 칸씩 뒤로 밀어야 한다.
i번 칸을 지우려면 이후를 한 칸씩 앞으로 당겨야 한다.

```c
// a[0..n) 에 유효한 값이 있다고 가정. 용량은 충분하다.
void insert_at(int a[], int *n, int i, int value) {
    for (int j = *n; j > i; j--) a[j] = a[j - 1];
    a[i] = value;
    (*n)++;
}

void erase_at(int a[], int *n, int i) {
    for (int j = i; j < *n - 1; j++) a[j] = a[j + 1];
    (*n)--;
}
```

한 번이 O(n)이다.
맨 앞에 넣으면 n칸을 밀고, 맨 뒤에 넣으면 밀 칸이 없어서 O(1)이다.
배열은 “중간을 자주 건드리는 구조”가 아니다.

### 맨 뒤 삽입/삭제는 싸다

크기를 나타내는 변수 n만 있으면

```c
a[n] = value;
n++;
```

이걸로 맨 뒤 삽입이 끝난다. O(1)
단, 미리 잡아 둔 용량을 넘으면 안 된다. 정적 배열의 한계가 여기다.
<br />

## 3. 배열이 잘 맞는 상황

크기가 미리 정해져 있거나, 인덱스가 곧 의미일 때 배열이 편하다.

### 카운팅

값이 0 이상 작은 정수일 때, 값 자체를 인덱스로 쓴다.

```c
int cnt[100001];

int main() {
    int n, x;
    scanf("%d", &n);
    for (int i = 0; i < n; i++) {
        scanf("%d", &x);
        cnt[x]++;
    }
}
```

등장 횟수 조회가 O(1)이다.
해시맵을 써도 되지만, 값의 범위가 10⁵ ~ 10⁶ 이하면 배열이 더 단순하고 빠르다.
코테에서 “1 ≤ aᵢ ≤ 100,000”이면 거의 반사적으로 카운트 배열을 떠올린다.

좌표가 10⁹까지면 배열로 못 잡는다. 그때는 좌표 압축을 해서 인덱스를 줄이거나 해시/트리를 쓴다.

### 누적합

구간 합을 O(1)에 답해야 할 때.

```c
int a[100001], p[100001];

// p[i] = a[1] + ... + a[i]
for (int i = 1; i <= n; i++) p[i] = p[i - 1] + a[i];

// a[l] + ... + a[r]
int range_sum = p[r] - p[l - 1];
```

전처리 O(n), 질의 하나 O(1)
2차원으로 올리면 그리드 구간 합도 같은 식으로 만든다.

### 방문 체크, 에라토스테네스

```c
int visit[100001];
int sieve[1000001];
```

정점 번호, 숫자 자체가 인덱스인 문제는 배열이 곧 집합이다.
visit[v] = 1 이 “집합에 v가 있다”와 같다.

### 인접 행렬

정점이 적으면 그래프를 2차원 배열로 둔다.

```c
int adj[401][401];
adj[u][v] = 1;
```

간선 여부 O(1)
정점이 400이면 16만 칸이라 문제 없고, 10만이면 100억 칸이라 불가능하다.
그때는 인접 리스트(벡터의 배열)로 바꾼다.

### 게임 보드, 타일맵

체스판, 테트리스, 로그라이크 던전, 2D 타일맵은 칸 수가 맵 제작 시점에 정해져 있다.

```c
enum { EMPTY = 0, WALL = 1, PLAYER = 2 };

int map[64][64];

int tile(int x, int y) {
    if (x < 0 || x >= 64 || y < 0 || y >= 64) return WALL;
    return map[y][x];
}
```

(x, y) 조회가 O(1)이라 매 프레임 충돌 검사에 부담이 없다.
맵 크기가 런타임에 바뀌는 오픈월드가 아니면 정적 2차원 배열이면 충분하다.

인벤토리 슬롯 30칸, 스킬 단축키 10칸, 주사위 눈 6개처럼 “칸 수가 기획으로 고정”인 것도 배열이다.

```c
int inventory[30];
int hotbar[10];
```

슬롯 번호가 곧 인덱스라 UI와 1:1로 대응한다.

### DP 테이블

```c
int dp[10001];
int dp2[501][501];
```

i번째 상태를 인덱스로 바로 연다.
코테에서 n ≤ 10⁴, n ≤ 500 같은 제한을 보는 이유 중 하나가 이 테이블을 배열로 잡을 수 있는지다.

n = 5000인 int dp[n][n]은 대략 100MB다. 메모리 제한 128MB면 아슬아슬하고, 한 줄만 남기는 최적화를 한다.
<br />

## 4. 배열이 불편한 상황

- 원소 개수가 실행 중에 크게 늘어난다. 채팅 로그, 생성된 적, 들어오는 패킷.
- 중간 삽입/삭제가 많다. 플레이어 이름순 리스트를 배열 한가운데에 계속 끼워 넣으면 매번 O(n).
- 칸마다 타입이 다르다. 그때는 구조체 배열이거나, 아예 다른 구조를 쓴다.

중간이 잦으면 연결 리스트나 트리 쪽을 보고,
맨 뒤만 건드리면 동적 배열이면 된다.
<br />

## 5. 동적 배열이란

길이가 실행 중에 늘어나고 줄어드는 배열이다.
C++ vector, Java ArrayList, Python list, Rust Vec이 이쪽이다.
겉으로는 배열처럼 a[i]로 접근하고, 속에서는 용량이 모자랄 때 더 큰 배열을 새로 잡아 복사한다.

핵심 변수는 두 개다.

- size: 지금 들어 있는 원소 수
- capacity: 실제로 할당해 둔 칸 수

size ≤ capacity
size가 capacity에 닿은 채로 삽입하면 보통 용량을 2배로 늘린다.

직접 짜 보면 동작이 드러난다.

```c
typedef struct {
    int *data;
    int size;
    int cap;
} IntVec;

void vec_init(IntVec *v) {
    v->data = NULL;
    v->size = 0;
    v->cap = 0;
}

void vec_push(IntVec *v, int x) {
    if (v->size == v->cap) {
        int ncap = (v->cap == 0) ? 1 : v->cap * 2;
        int *nd = realloc(v->data, sizeof(int) * ncap);
        v->data = nd;
        v->cap = ncap;
    }
    v->data[v->size++] = x;
}

int vec_get(IntVec *v, int i) {
    return v->data[i];
}

void vec_pop(IntVec *v) {
    if (v->size > 0) v->size--;
}

void vec_free(IntVec *v) {
    free(v->data);
    v->data = NULL;
    v->size = v->cap = 0;
}
```

접근 vec_get은 O(1)
맨 뒤 삽입 vec_push는 용량이 남아 있으면 O(1), 재할당이면 그 한 번은 O(n)
맨 뒤 삭제는 보통 칸을 반납하지 않고 size만 줄인다. O(1)

## 6. 왜 두 배씩 늘리는가

한 칸씩만 늘리면 n개를 넣을 때 복사 횟수가

1 + 2 + 3 + … + (n-1) = Θ(n²)

가 된다. push n번이 O(n²)이라 동적 배열을 쓰는 의미가 없다.

2배씩 늘리면 용량이 1, 2, 4, …, n으로 늘어나고 복사 총합은

1 + 2 + 4 + … + n ≤ 2n

이다. n번 push의 총비용이 O(n)이므로 한 번의 상각 비용은 O(1)이다.
최악 한 방은 여전히 O(n)이다. 그 한 방을 피하고 싶으면 미리 용량을 예약한다.

```cpp
vector<int> v;
v.reserve(100000);
for (int i = 0; i < 100000; i++) v.push_back(i);
```

reserve를 해 두면 루프 안에서 재할당이 안 일어난다.
코테에서 n 최댓값을 알면 처음부터 v.resize(n) 하거나 reserve(n) 하는 버릇이 있다.

늘리는 배수가 1.5인 구현도 있다. 메모리 낭비를 줄이는 대신 재할당이 조금 더 잦다.
어느 쪽이든 상각 O(1)은 유지된다.
<br />

## 7. 동적 배열의 연산

C++ vector 기준으로 보면

- v[i], v.front(), v.back(): O(1)
- v.push_back(x), v.pop_back(): 상각 O(1)
- v.size(), v.empty(): O(1)
- 맨 앞 insert / erase: O(n). 전체를 민다
- 중간 insert / erase: O(n)
- 전체 순회: O(n)
- clear(): 보통 size만 0. capacity는 남는 구현이 많다

Java ArrayList, Python list도 맨 뒤 추가는 상각 O(1), 맨 앞 삽입은 O(n)으로 같다.
Python list.pop(0)이 느린 이유가 이것이다. 맨 앞을 자주 빼면 deque를 쓴다.

재할당이 일어나면 기존 원소의 주소가 바뀐다.

```cpp
vector<int> v = {1, 2, 3};
int *p = &v[0];
v.push_back(4);   // cap이 3이었으면 재할당
// p는 이미 해제된 곳을 가리킬 수 있다
```

포인터나 iterator를 잡아 둔 채로 push를 반복하면 터진다.
인덱스만 저장하거나, 삽입이 끝난 뒤에 주소를 얻으면 된다.

## 8. 정적 배열과 동적 배열

정적 배열
- 크기 고정
- 선언이 단순하다
- 스택에 두면 할당이 빠르지만, 너무 크면 스택 오버플로
- 전역으로 잡으면 수 MB ~ 수십 MB까지는 코테에서 흔하다

동적 배열
- 크기가 변한다
- 힙을 쓰므로 큰 데이터도 가능하다
- 재할당, reserve, 포인터 무효화를 알아야 한다
- 원소가 늘 때마다 늘어나서, “최대 몇 개일지”를 몰라도 된다

크기를 컴파일 전에 알고 있고 절대 안 변하면 정적 배열이 더 단순하다.
게임 타일맵 128×128, 포커 손패 5장, 주사위 6면이 그 경우다.

크기를 입력으로 받거나 실행 중에 쌓이면 동적 배열이다.
코테 입력 n개, 게임에서 스폰된 적, 서버에 접속 중인 유저 목록이 그 경우다.

둘을 같이 쓰기도 한다.
인접 리스트는 “정점 수만큼의 동적 배열”이다.

```cpp
vector<int> adj[100001];
adj[u].push_back(v);
adj[v].push_back(u);
```

정점 번호는 고정 인덱스, 각 정점의 이웃 수는 제각각이라 안쪽에 vector를 둔다.

## 9. 코테에서

입력이 n ≤ 10⁵, 10⁶이면 거의 항상 배열 또는 vector다.
연결 리스트를 직접 짜서 쓰는 문제는 드물다.

자주 나오는 패턴:

입력 저장

```cpp
int n;
cin >> n;
vector<int> a(n);
for (int i = 0; i < n; i++) cin >> a[i];
```

처음부터 n칸을 잡아 두면 push 없이 끝난다.

전역 정적 배열

```cpp
int a[1000001];
```

C++에서 함수 안 큰 배열은 스택 터짐이 난다.
전역이나 static으로 두거나 vector를 쓴다.

그래프

```cpp
vector<pair<int,int>> adj[100001];
```

BFS/DFS의 방문 배열은 정적 배열이 흔하다.

```cpp
int visit[100001];
int dist[100001];
```

정점 번호가 1..n이라 인덱스가 곧 정점이다.

투 포인터, 슬라이딩 윈도우, 정렬 후 이분 탐색
전부 배열 위에 올린 알고리즘이다.
정렬은 랜덤 접근이 되어야 해서 리스트보다 배열이 맞다.

크기 제한만 보고 정적 배열을 쓸지 vector를 쓸지 고르면 된다.
n 최댓값이 문제에 적혀 있으면

```cpp
int a[200001];
```

도 되고

```cpp
vector<int> a;
a.reserve(n);
```

도 된다. 팀 코드 스타일 차이다.

주의할 점:

- 중간 erase를 반복하면 O(n²)이 된다. 조건에 맞는 원소만 남길 때는 새 벡터에 push 하는 편이 낫다.
- vector<vector<int>> dp(n, vector<int>(n)) 은 행마다 따로 할당이라 캐시가 아프다. n이 크면 int dp[n*n]처럼 한 줄로 펴는 쪽이 빠르다.
- 0-index / 1-index를 섞으면 바로 틀린다. 누적합은 1-index가 편하고, 입력 배열은 0-index가 편하다. 하나만 정해서 간다.

## 10. 게임에서

프레임마다 전체를 순회해야 하는 데이터가 배열(또는 동적 배열)과 잘 맞는다.
칸이 붙어 있어서 적 1000마리의 hp를 갱신하는 루프가 캐시를 탄다.

고정 크기 → 정적 배열에 가까운 것

- 타일맵, 충돌 그리드
- 인벤토리 슬롯, 장비 칸
- 키 바인딩, 게임패드 버튼 상태
- 한 판의 점수 보드 10등까지

```c
int scoreboard[10];
```

등수가 곧 인덱스다.

늘어나는 것 → 동적 배열

- 살아 있는 적, 총알, 파티클, 플로팅 데미지
- 채팅 로그, 최근에 받은 히트 기록
- 에디터에서 찍은 웨이포인트

```cpp
struct Bullet {
    float x, y, vx, vy;
    int ttl;
};

vector<Bullet> bullets;

void spawn_bullet(float x, float y, float vx, float vy) {
    bullets.push_back({x, y, vx, vy, 60});
}

void update_bullets() {
    for (int i = 0; i < (int)bullets.size(); ) {
        bullets[i].x += bullets[i].vx;
        bullets[i].y += bullets[i].vy;
        bullets[i].ttl--;
        if (bullets[i].ttl <= 0) {
            bullets[i] = bullets.back();
            bullets.pop_back();
        } else {
            i++;
        }
    }
}
```

순서가 상관 없는 총알이면, 중간 erase 대신 마지막 원소와 자리를 바꾸고 pop_back 한다.
한 발 제거가 O(1)이다. 매 프레임 수백 발이 사라지고 생기면 이 차이가 크다.

엔티티 수가 상한에 가까우면 오브젝트 풀을 쓴다.
미리 Bullet pool[MAX]를 잡아 두고, 살아있는 인덱스만 동적 배열로 들고 있는 식이다.
할당을 프레임 중간에 안 하려고 하는 기법이다.
엔티티 상한이 128이면 정적 배열 + 활성 플래그로도 충분하다.

컴포넌트 시스템에서도 같은 종류 컴포넌트를 배열로 붙여 둔다.
Position[i], Velocity[i]를 나란히 돌리는 편이 객체 하나마다 malloc 하는 것보다 캐시가 낫다.

네트워크 스냅샷, 리플레이도 프레임 단위 배열이다.
“이번 프레임에 일어난 입력 40개”처럼 짧은 건 고정 배열, “매치 전체 로그”는 동적 배열이다.

## 11. 2차원 배열

정적

```c
int a[100][200];
// a[i][j]
```

메모리는 한 줄로 펼쳐져 있다. a[i][j]의 위치는 i * 200 + j 근처다.
행 우선이라서 a[i][0], a[i][1], … 순서가 캐시에 잘 맞는다.
이중 루프는 바깥을 행, 안쪽을 열로 도는 쪽이 빠르다.

동적 2차원은 두 가지가 있다.

```cpp
vector<vector<int>> a(h, vector<int>(w));
```

구현이 편하다. 행마다 길이가 달라도 된다.
행마다 할당이 따로라서 큰 격자에서는 한 줄 배열보다 느리다.

```cpp
vector<int> a(h * w);
int at(int y, int x) { return a[y * w + x]; }
```

할당이 한 번이고 칸이 붙는다.
타일맵, 이미지 버퍼, 큰 DP가 이쪽에 잘 맞는다.

## 12. 같이 보면 되는 선택

맨 앞과 맨 뒤를 둘 다 자주 건드린다 → deque
중간 삽입/삭제가 많고 순서가 중요하다 → list. 다만 코테에서는 거의 안 이기고, 게임에서도 캐시 때문에 비호감인 경우가 많다
키로 찾고 싶다 → 해시맵, 트리맵. 값 범위가 작으면 그냥 배열
좌표가 크고 등장하는 값만 쓴다 → 해시 or 좌표 압축 후 배열
그래프 이웃 → vector 배열
매 프레임 순회 + 생성/삭제 → 동적 배열 + swap-pop, 또는 풀

배열과 동적 배열은 “인덱스로 O(1) 접근이 되고, 맨 뒤를 만지는 비용이 싸다”는 같은 가족이다.
크기가 고정이면 배열, 커질 수 있으면 동적 배열을 쓰면 된다.
